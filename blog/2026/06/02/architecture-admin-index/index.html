08-架构 只有 5 篇，但跨度大：从 OA Monorepo 脚手架 到 多地域门户权限。缺少总览时，读者容易 直接打开门户深文然后放弃。本篇说明 每篇解决什么问题、要先懂什么、建议阅读顺序。

一、五篇文章各自解决什么

文章解决什么问题难度
动态表单与 ProTable中后台 CRUD 怎么少写重复代码⭐⭐
OA Monorepo 前端架构（在新窗口打开）多包仓库、契约客户端、路由即菜单⭐⭐⭐
BFF Protobuf RPC 客户端栈浏览器只打 HTTP，BFF 怎么调内部 RPC⭐⭐⭐⭐
文件预览水印下载附件链路安全⭐⭐⭐
多地域门户场景策略一套代码多形态、权限三源合成⭐⭐⭐⭐⭐

二、读前应先具备的概念

概念一句话不懂先读
中后台 / Admin登录后的运营管理界面，重表格表单ProTable 文
RBAC按角色分配权限码RBAC 导读
Monorepo一个 Git 仓多个 packagepnpm workspace（在新窗口打开）
BFFBackend For Frontend，为 UI 定制的 API 层下文第三节 · BFF RPC 文
Protobuf / RPC二进制契约 + 内部服务调用，浏览器通常不直连BFF RPC 文
动态路由菜单/路由由接口下发，非写死在代码里Vue Router 权限
Ticket / 签名 URL短期授权访问文件，非永久 OSS 链接文件预览文

三、BFF 是什么（30 秒版）

浏览器 ──HTTP/JSON──► BFF（Node/Java）──RPC/SQL──► 内部微服务
         ↑
    字段贴合 UI、聚合多接口、藏密钥

不是 把 Java 接口原样暴露给前端；是 减少往返、统一鉴权、适配多端。Protobuf 文讲的是 BFF 如何生成类型安全的 RPC 客户端。

四、推荐阅读顺序

路径 A：中后台脚手架（多数团队）

  1. ProTable / 动态表单
  2. RBAC 建模 → 数据权限
  3. Vue Router 动态菜单
  4. OA Monorepo 架构（在新窗口打开）
  5. 文件预览链路

路径 B：大型门户 / 多地域（进阶）

在路径 A 基础上，再读 门户场景策略 —— 文首有 场景策略 101。

路径 C：BFF / 内部 RPC

  1. Egg 架构（在新窗口打开）（Node 读者）
  2. BFF Protobuf RPC 栈

五、与微前端、企业级的关系

  • 微前端：多个独立前端应用组合 → 微前端导读
  • 企业级发版：架构定完还要 CI/网关/观测 → 企业级导读
  • 工程化总地图 → 工程化导读

六、一句话

中后台架构 = RBAC + 动态路由 +（可选）BFF +（可选）Monorepo；门户深文是 在前三者之上加「场景策略」，别跳过基础直接读第五篇。
